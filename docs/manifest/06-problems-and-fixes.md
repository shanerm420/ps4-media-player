# 6. Problems and fixes

| **The logged GPU test's log came back empty** | unknown, and v1 could not report on itself: its `freopen` return was discarded | **Answered 2026-11-23, in the useful half.** Verified: v1's `eboot.bin` carries `/data/piglet-gpu-test.log`, so the redirect was compiled in; the owner says both packages ran the same way. Causes, most to least likely: (1) the redirect failed silently — not the path, which v3 proved writable, but `freopen`/stdio in this libc — and every line went to a stdout nobody can read, which fits "it ran the same as the shipped build"; (2) the pull happened before any flush, or in a transfer mode that produced a 0-byte local file; (3) a crash or hang before the first print; (4) output on a path the redirect does not cover. Ruled out: a wrong package — the archived pkg's eboot contains the path string. v3 answered both open halves: three of its six paths opened, `/data` root included (`path OK /data/piglet-gpu-test-v3.log (fd 5)`), so the filesystem was never the problem; what failed in v1 is the `freopen` on stdout. Nothing else in the run was lost — v3 wrote 3,300 frames' worth of log. **Three other logs the owner found — `Loader_Logs.txt`, `memory.log`, `UnityOrbisBridge.log` — were read and ruled out** ([§9](09-ps4-knowledge-base.md)): none of them mentions BREW00093, Piglet, EGL or GL. |
| **Two files named `piglet-gpu-test-v3.log` came back, one 1,137 bytes shorter** | the logger opens three sinks and redirects fd 1 at the first, so only that one also receives the sample's own `printf` output | **Explained, not a fault.** Both files are the same run to the millisecond (first line 0.026, last line 28.104, the same 56 heartbeats), so they cannot be two runs and neither is truncated. The 8,343-byte file carries `Loading modules...`, `GL_RENDERER: Piglet` and the uniform dump, so it is `/data/piglet-gpu-test-v3.log`; the 7,206-byte copy is one of the two secondary sinks (`/data/pkg/` or `/data/ultimate-ps4-media-player/`), which are byte-identical to each other — which one it is depends on the folder it was pulled from, and both hold every logger line. Next time: one sink, plus the sample's own output through the same fd. |
| `boot: libGLESv2 rc=0x80020002`, then `SDL_GL_LoadLibrary No dynamic GL support in current SDL video driver (PS4)` | there is **no `libGLESv2.sprx`** on this console's system paths — `0x80020002` is the same code the v3 log gets for an unmounted USB stick | **Not a defect and not a path problem.** Piglet is the GL implementation here and is loaded by name (`libScePigletv2VSH.sprx`, `module_start() = 0`), not through SDL's `libGLESv2` lookup. BREW00096 runs the loop instead of exiting, because the pre-render check drains the pending error first. Still to fix: the sample's draw itself, which a port cannot inherit. |
| **Bloom 3 drove the blur with a vec4 where the shader wants a vec2** | `u_blurRadius` is `GL_FLOAT_VEC2` (0x8B50); `glUniform4f` was rejected | **Fixed twice over.** A2 corrected the type; A5 found the real cause and BREW00102 confirms it: all 23 `SET` lines read `accepted` once the program is bound. The `glGenQueries`-without-`EXT` lead was taken up in BREW00103, which asks for the entry points and says so in the log if they are absent. |
| **The v118 `video: SRC` line prints `codec=` empty** | the `stsd` scan in `src_probe()` matched something that is not a sample entry, so the fourcc came out as NUL bytes | **Open, cosmetic.** `brand=isom` and `bytes=508151141` are correct, so the file and the probe agree; only the fourcc is blank. Real answer for this file is AVC/HEVC in an `isom` container, but that is inference — the next build should read the box tree properly or drop the field. |

| **Round 2's bloom chain cannot be written as GLSL** | no shader compiler here; Piglet takes precompiled blobs from `libScePrecompiledShaders.sprx` | **Gate passed 2026-11-24.** The blobs exist and run: the probe fetches `texmap`, `bright`, `blur1`, `blur2` (`PROG … link=1`, six uniforms each on the blurs) and draws a real chain at 480x270 between 1080p targets.
