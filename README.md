# Ultimate PS4 Media Player

A native PS4 (OpenOrbis) media player. MP3 and MP4/MOV both play: audio goes
decode → resample → 10-band EQ → volume → soft limiter → `sceAudioOut`, video
through the firmware's AvPlayer with the same audio chain, an SDL2 UI and a PKG
build that installs as **Ultimate PS4 Media Player**.

> **Status:** builds, links and packages cleanly; the host-side audio and
> subtitle code passes 27 assertions and every screen is rendered at 720p,
> 1080p and 1440p in `preview/`. It has **not been run on a retail console yet**,
> so playback timing, colour and USB numbering still need a hardware pass.
> Built against OpenOrbis toolchain v0.5.4 on Ubuntu 24.04.

The latest build is attached to

`IV0000-BREWMEDI1_00-ULTIMATEMEDIA000.pkg` (6.6 MB). It is fake-signed, so the

[Quick start](#quick-start).

## What it does

* **Plays MP3** with a 10-band equalizer, preamp, volume in dB and a soft
  limiter before `sceAudioOut`.
* **Plays MP4/MOV** through the console's own `libSceAvPlayer` (H.264), with the
  equalizer and volume chain applied to the video's audio too.
* **Browses every place media can live** — internal drive, USB ports, extended
  storage, legacy Linux mounts — with folders, file-type tags and a rescan.
* **Video settings card**: aspect ratio (fit / fill / stretch), brightness,
  subtitle file and subtitle size, all applied live without re-decoding.
* **Sidecar subtitles** (`.srt` / `.vtt`): loaded automatically, cycled in the
  settings card, and toggled with **Options** during playback with a fading
  `SUBTITLES ON` / `SUBTITLES OFF` confirmation.
* **A television UI**: Inter type scale sized from published TV guidelines, safe
  margins, controller buttons drawn as buttons, and a layout that rescales to
  the renderer's real output size every frame (720p, 1080p, 1440p).

```

src/mp3_source.c   MP3 file source on minimp3                      [tested]
src/audio_out_orbis.c  sceAudioOut wrapper                         [needs PS4]
src/video_orbis.c  AvPlayer: file I/O, YUV->RGBA, audio to the mixer  [needs PS4]
src/subtitles.c    sidecar .srt / .vtt parser and cue timing         [tested]
src/ui.c           all screen drawing (panels, lists, EQ, text)    [previewed]
src/font_atlas.c   draws text from a pre-rendered glyph atlas        [tested]
src/font_inter.h   Inter at 36 px, 8-bit alpha atlas + metrics      [generated by make deps]
```

## Quick start

```bash
# 1. get the source and the two fetched/generated pieces
#    (minimp3.h and the Inter glyph atlas; both pinned by SHA-256)
git clone https://github.com/shanerm420/ps4-media-player.git
cd ps4-media-player
make deps

# 2. put the OpenOrbis toolchain somewhere and point the build at it
export OO_PS4_TOOLCHAIN=$HOME/OpenOrbis-PS4-Toolchain
make              # -> eboot.bin + IV0000-BREWMEDI1_00-ULTIMATEMEDIA000.pkg
```

`make deps` needs `curl` (or `wget`) and Python 3 with Pillow
(`pip install pillow`). Without it the build still succeeds, but with the
bundled 8x8 pixel font instead of Inter and no MP3 decoder, so run it first.

### Install on the console

The package is fake-signed, so the console must be jailbroken with HEN/GoldHEN
running. This is the same step the [download](#download) skips past.

1. Copy the `.pkg` to the root of a USB stick (FAT32 or exFAT) or FTP it to
   `/data/pkg/`.
2. On the PS4 open **Settings → Debug Settings → Game → Package Installer**
   (GoldHEN) and install the file.
3. Launch **Ultimate PS4 Media Player** from the home screen.

Media is read from the folders listed under *Where it looks for media* below.
Drop files on a USB stick root or in its `music/` folder and press **Square** to
rescan. Subtitles go next to the video with the same name (`movie.mp4` →
`movie.srt`, `movie.en.srt`, or a `.vtt` variant).

If `make` fails at the packaging step with
`No usable version of libssl was found`, see *Building the PKG* for the
libssl 1.1 workaround.

## Interface

Two screens and a footer:

* **Drive browser** (the screen it starts on): one row per mounted drive -
  `INTERNAL DRIVE`, `INTERNAL MUSIC`, `USB 1` .. `USB 8`, `EXTENDED STORAGE` -
  plus `ALL MEDIA (LIBRARY)` and `REFRESH DRIVE SCAN`. X opens a drive, folders
  are rows you can enter, and media files are tagged `MP3` or `VIDEO`, so a
  folder called `music` never looks like a file called `music`. Breadcrumbs sit
  above the list (`DRIVES`, then the full path) with an item count on the right.
  Only mounts that actually opened are listed, so an empty port never appears.
  Refreshing keeps whatever is playing and drops back to the drive list if the
  drive you were browsing was unplugged.
* **Library** (left) owns the track list: numbered rows, the selected row is
  filled with an accent bar, the playing row is cyan and marked `ON AIR`, and
  the list scrolls to keep the selection visible. Long file names are cut with
  `...` rather than running into the tag column.
* **Now playing** (right): track name, format line (`MP3  44100 HZ  STEREO`),
  a progress bar with elapsed and total time, the volume bar in dB, and a small
  live plot of the ten EQ bands.
* **Equalizer overlay** (Triangle): ten bands plus preamp, values in dB, the
  selected band highlighted, adjusted with up/down and left/right.
* **Header**: title, one-line status, the PlayStation 4 wordmark and a
  playing/paused chip. The wordmark is drawn from `src/ps4logo.h`, a 1-bit span
  table generated by `tools/make-logo-h.py`, so there is no image to load and
  no SDL_image dependency.
* **Footer**: the controller map, so the screen explains itself. Buttons are
  drawn as the button - a dark disc with the Cross, Circle, Square or Triangle
  mark inside, a pill for L1/R1, an arrow for the d-pad, the three-node share
  mark for SHARE - followed by the action name, instead of writing "X" or
  "TRIANGLE". Every mark comes from primitives (`btn_chip` in `src/ui.c`), so
  there is still no icon sprite to ship.

Sizes are set for a television, not a desk. That is a well-covered problem, and
this layout follows the published numbers rather than taste:

* **Xbox Accessibility Guideline 101** - console text must be at least 26 px at
  1080p;
* **Amazon Fire TV** - body text around 28 px at 1080p, and no UI inside the
  outer 5% of any edge;
* **Apple tvOS layout** - 60 pt top and bottom, 80-90 pt sides at 1080p;
* **Android TV** - a 5% safe margin on every edge.

Nothing is welded to 1920x1080 at runtime either: the main loop asks the
renderer for its real output size every frame (`SDL_GetRendererOutputSize`) and
passes it to the UI, which scales glyph sizes along with the rectangles. At
720p the text shrinks with the panels instead of spilling out of them, and at
1440p it grows with them; `preview/out-main-720.png`, `out-video-720.png` and
`out-main-1440.png` are renders of that check.

So the type scale is 20 px captions (short, upper-case labels only), 26 px body
and buttons, 40 px panel titles and a 54 px app title, nothing readable below
20 px, with 96 px side and 60 px top/bottom margins. Rows are 78 px tall, the
controller chips are 44 px discs, and the safe area is respected by the footer
and the subtitles as well, so overscan cannot clip an action label.

Text is **Inter**, chosen for legibility at television distance. The console
build has no font rasteriser, so the face is rendered on a PC into an 8-bit
alpha atlas (`src/font_inter.h`, about 62 KB) and blitted as one texture: the
anti-aliasing survives and there is no font file to ship. Panels are rounded
rects and bars come from primitives, so nothing is loaded from disk at runtime.
The layout is authored at 1920x1080 and scales to whatever surface it is given.

To change the face (or the size), regenerate the atlas - no other code changes:

```bash
python3 tools/make-font-atlas.py Inter.ttf --name font_inter --size 36 > src/font_inter.h
```

Building without `-DUI_FONT_ATLAS` falls back to the bundled 8x8 pixel font in
`third_party/font8x8.c`, which is still there as a zero-dependency fallback.

The interface is verified by rendering it, not by guessing:

```bash
make -C preview run     # -> preview/out-*.bmp, one per screen and per size
```

That builds `src/ui.c` against host SDL2 with the dummy video driver, fills a
demo model (including a deliberate over-long file name, a video entry, a drive
list and a subtitle) and writes every screen: `out-browser.png`,
`out-main.png`, `out-eq.png`, `out-video.png`, `out-settings.png` and
`out-fullscreen.png`. This catches layout faults - overlapping text, malformed rounded
corners, bars that overflow their panel - that only show up when you look.

## Verified on a PC

`make -C test run MP3=/path/to/file.mp3` builds the platform-independent half
with gcc and checks it against any short MP3 you point it at (27 assertions:
the audio path below plus the subtitle parser, all passing). No audio file is
committed; generate one with
`ffmpeg -f lavfi -i "sine=1" -t 1 /tmp/test.mp3` if you need one.

```
flat EQ is bit-transparent                                 PASS
+12 dB @1k gives ~4.0x on a 1 kHz tone                     PASS   3.981x
-12 dB @1k gives ~0.25x on a 1 kHz tone                    PASS   0.251x
band above Nyquist is bypassed (8 kHz stream)              PASS
44.1k -> 48k produces ~1 s of output                       PASS   47999 frames
pitch preserved (zero crossings ~1000)                     PASS   1000
-6.02 dB gives 0.5x gain                                   PASS
soft limiter holds full scale at 1.0                       PASS
limiter is transparent below the knee                      PASS
s16 conversion clamps instead of wrapping                  PASS
MP3 opens / decodes / reports format / no NaN / duration   PASS   8000 Hz mono, 1.15 s
```

Building this caught two real bugs in the decoder wrapper: a padding frame with
no valid header was zeroing the stream format (duration read 0.00 s), and EOF
during resync never set the finished flag. Both are fixed.

## Building the PKG

Verified end to end on Ubuntu 24.04 with toolchain **v0.5.4**. Three things are
needed beyond the toolchain itself; each cost a build failure to find.

```bash
# 1. toolchain (Linux binaries live in bin/linux)
curl -fL -o tc.tar.gz \
  https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/releases/download/v0.5.4/toolchain-llvm-18.tar.gz
tar xzf tc.tar.gz --strip-components=2 -C OpenOrbis-PS4-Toolchain

# 2. SDL2 headers (libSDL2.a ships in the toolchain, the headers do not)
curl -fL -o sdl2.tar.gz \
  https://github.com/OpenOrbis/SDL-PS4/releases/download/v1.0/SDL2.tar.gz
tar xzf sdl2.tar.gz -C OpenOrbis-PS4-Toolchain

# 3. libssl1.1 for PkgTool.Core (a .NET binary; 24.04 ships OpenSSL 3 and it
#    aborts with "No usable version of libssl was found")
#    fetch libssl1.1 from the focal archive and unpack it somewhere private, e.g.
#    ~/libssl11/usr/lib/x86_64-linux-gnu/libssl.so.1.1

make OO_PS4_TOOLCHAIN=$PWD/OpenOrbis-PS4-Toolchain \
     PKG_LD=$HOME/libssl11/usr/lib/x86_64-linux-gnu
```

`make` produces `eboot.bin` (2.2 MB SELF) and
`IV0000-BREWMEDI1_00-ULTIMATEMEDIA000.pkg` (6.6 MB). The XMB shows the `TITLE`
from the SFO: **Ultimate PS4 Media Player**. Drop a 512x512 `sce_sys/icon0.png`
in to get a tile as well (it is picked up by `PKGFILES`; without one the tile is
simply blank). Sanity-check the result:

```
xxd -l 4 *.pkg        # 7f 43 4e 54  = .CNT
```

Things that were wrong in the first draft of this Makefile, now fixed:

* the Content ID was 38 characters; the PS4 requires exactly 36
  (6 + 1 + 12 + 1 + 16), with the middle 12 being the 9-character `TITLE_ID`
  plus `_00`. `PkgTool` refuses anything else;
* `-lSDL2` pulls in `sceVideoOut*`, so `-lSceVideoOut` and `-lSceCommonDialog`
  must follow it on the link line or the link fails on undefined symbols;
* `PkgTool.Core` needs `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1` (exported by
  the Makefile) or it dies looking for ICU.

A PKG can be built with no assets at all; the icon and background image are
cosmetic. Copy them from the toolchain's own samples if wanted:

```
sce_sys/icon0.png
sce_sys/about/right.sprx
```

The package is fake-signed, so it installs only on a jailbroken console with
HEN/GoldHEN running. The player scans every place media can live:

* **Internal hard drive** — `/data/music` and `/data/linux/music` (the app's own
  folder is under `/data`, so this is always reachable).
* **USB drives** — `/mnt/usb0` through `/mnt/usb7`, each scanned directly and in
  its `music/` subfolder. The ports are numbered in plug order, so the two front
  ports and the rear one all appear here; 8 devices is the console's limit.
* **Extended storage** — `/mnt/ext0` and `/mnt/ext0/music`.
* **Legacy Linux installs** — `/usb0/music` and `/usb1/music`.

Mount points that are not mounted simply fail to open and are skipped, so an
empty port costs nothing. Files dumped at the root of a USB stick are found
too, and a path reached twice is only listed once.

|---|---|
| D-pad up/down | select track |
| X | play / pause |
| Square | stop |
| L1 / R1 | previous / next track |
| D-pad left/right | volume −3 / +3 dB |
| Triangle | equalizer overlay (up/down = ±1 dB, left/right = band, preamp is the band after 16 kHz) |
| SHARE | open the drive browser |
| Circle | quit |

In the drive browser:

| Button | Action |
|---|---|
| D-pad up/down | move through drives, folders and files |
| L1 / R1 | page up / page down |
| X | open a drive or folder, play the selected file |
| Square | rescan the drives and folders |
| Circle | one level up, then back to the library |
| Triangle | equalizer |
| SHARE | back to the library (or pick `ALL MEDIA (LIBRARY)`) |

While a video is on screen:

| Button | Action |
|---|---|
| X | pause / resume |
| D-pad left/right | seek 10 s back / forward |
| Square | stop and return to the library |
| L1 / R1 | previous / next file |
| Triangle | video settings card |
| Options | subtitles on / off, with a short confirmation that fades out |
| Circle | back to the library (does not quit) |

Any button brings the transport bar back; on its own it hides again 3 seconds
into playback, leaving just the picture and any subtitles. Pausing, seeking or
opening the settings keeps it on screen.

Inside the settings card: up/down picks a row, left/right changes it, Triangle
or Circle closes it.

| Row | Values |
|---|---|
| Aspect ratio | FIT (whole frame), FILL (crop to cover), STRETCH (fill, distorted) |
| Brightness | −100 … +100, applied to the picture only |
| Subtitles | OFF, or each sidecar file found next to the video |
| Subtitle size | SMALL / NORMAL / LARGE |

## Video

MP4/MOV plays through `libSceAvPlayer`, the firmware's own demuxer and decoder,
which is the only realistic way to get 1080p H.264 out of this hardware. The
library decodes; `src/video_orbis.c` provides everything around it.

OpenOrbis ships the library as NID stubs with no prototypes at all
(`void sceAvPlayerInit();`), so the ABI is declared in `video_orbis.c` from two
independent PS4 implementations that agree field for field: shadPS4
(`core/libraries/avplayer/avplayer.h`) and fpPS4
(`src/ps4_libsceavplayer.pas`). The calls link against the firmware stub
library in the toolchain, and the SELF records a dependency on
`libSceAvPlayer.prx`.

Per playback the code supplies:

* **Init** — AvPlayer refuses to start without four allocators. They are
  alignment-correcting wrappers over `malloc` that stash the base pointer just
  before the aligned block so `free` gets it back.
* **File I/O** — open / close / read-at-offset / size callbacks, so a path under
  `/data`, `/mnt/usb0` or `/mnt/ext0` plays as-is, without library mounts.
* **Video** — `sceAvPlayerGetVideoDataEx` returns 8-bit YUV420 frames. They are
  converted to RGBA with BT.601 integer maths and uploaded to one SDL streaming
  texture, recreated only when the resolution changes. 10-bit files are refused
  rather than shown with wrong colour.
* **Audio** — `sceAvPlayerGetAudioData` returns interleaved 16-bit PCM at the
  track's own rate. It becomes float, is resampled to 48 kHz and downmixed to
  stereo, then joins the same EQ / volume / limiter chain as the MP3 path, so the
  equalizer applies to video as well.

### Video settings

Triangle opens a settings card over the picture. None of these touch the
decoded stream, so changing them mid-playback is instant and never re-decodes:

* **Aspect ratio** — `FIT` letterboxes the whole frame, `FILL` scales up until
  the frame covers the screen and crops the overhang, `STRETCH` fills the screen
  and ignores the source ratio for files that were authored with a wrong one.
* **Brightness** — a black or white veil drawn over the picture rectangle
  (blended fill, so it costs one draw call per frame) rather than a filter on
  every video frame.
* **Subtitles** — sidecar files are loaded from the video's own folder:
  `movie.srt`, `movie.vtt`, `movie.en.srt`, `movie.en.vtt`, matched by stem and
  case-insensitively, so a release folder is picked up with no setup. The
  parser handles SRT and WebVTT (detected by content, not extension), strips
  `<i>`/`<b>`/`{\an8}`-style markup, keeps line breaks inside a cue and uses a
  binary search for the cue at the current decoder time. Up to eight files per
  video; the row cycles through them and then to `OFF`. **Options** flips them
  on and off in one press while a video plays, showing `SUBTITLES ON` or
  `SUBTITLES OFF` over the picture (or `NO SUBTITLE FILES`) for about a second
  and a half before it fades away.
* **Subtitle size** — three sizes for the wrapped caption, drawn on one
  semi-transparent plate above the transport bar.

Limitations worth knowing: captions are ASCII — the Inter atlas has no Cyrillic
or CJK glyphs, so those characters will not draw; and subtitles embedded inside
the container are not rendered, because the OpenOrbis AvPlayer stubs expose no
call to pull timed-text frames (only the streams are enumerable).

Two assumptions are marked in the source, because they are the places to look
first if a title misbehaves:

1. the frame layout is NV12 — one luma plane, then interleaved U/V — rather than
   planar I420, which is how both reference implementations pack it;
2. seeking uses `sceAvPlayerJumpToTime(handle, ms)`, which not every firmware
   may implement identically.

**This has been compiled, linked and packaged, but never run on a console.**
Frame timing, colour and audio drift are the things only hardware can answer.

* OpenOrbis PS4 Toolchain — <https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain>

  <https://github.com/Rissx223/PS4-IPTV-Player>.

## What this player does not do (yet)

* AAC, FLAC, OGG/Opus, WAV — only the MP3 path is implemented; each additional
  codec is another decoder plus a container probe.
* Network streams, playlists (.m3u), gapless/replaygain.
* Subtitle tracks embedded in the container, and non-ASCII subtitle text — only
  sidecar `.srt`/`.vtt` files in the Latin atlas are drawn.
* Video-side EQ (the EQ here is the audio path).

## Plan

1. **MP3 player** — done on the audio side (tested), needs a hardware pass for
   `sceAudioOut` timing and the SDL2 UI.
2. **Video** — implemented with aspect / brightness / subtitle settings; needs a
   hardware pass for frame pacing, colour, A/V drift and subtitle timing, and a
   decision on NV12 vs I420 if the reference layout is wrong.
3. **Codecs** — add WAV (trivial), then FLAC (dr_flac), then Vorbis/Opus.
4. **Library** — playlists, folder navigation, metadata from ID3 tags.
